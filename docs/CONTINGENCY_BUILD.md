# Contingency MVP branch

Branch: `contingency/john-complete-mvp`

Purpose: maintain a complete, submission-safe ProofStack implementation that does not depend on unfinished teammate branches, NVIDIA event access, or external hackathon participation.

## Delivery assumptions

For contingency planning, assume:
- the team does **not** receive usable NVIDIA event credentials
- the team does **not** rely on either external hackathon for implementation
- Google Cloud remains the platform learned during the program
- Vertex AI / Gemini is the intended live model provider
- Cloud Run hosts the Streamlit application
- Firestore stores reviewer decisions
- mock mode remains an offline/demo safety net

If NVIDIA access unexpectedly appears later, it is an optional enhancement rather than a dependency.

## Rules

1. This branch is explicitly John-owned contingency work.
2. Do not rewrite Git history to make contingency work appear to be another teammate's contribution.
3. If a teammate later delivers a stronger implementation, review and merge/cherry-pick that contribution normally.
4. Manual gold labels remain a human task and are not generated by this branch.
5. Final metrics are not run until the manual gold set is complete and frozen.
6. Live Vertex, Cloud Run and Firestore status must be reported exactly as verified.
7. NVIDIA must not appear in final claims unless its smoke test actually succeeds.
8. Hackathon participation must not be implied if it did not occur.
9. The contingency branch may become the submission base if required, but only after contribution history and final facts are reconciled.

## Primary delivery path

```text
Synthetic questionnaire/evidence
        ↓
Streamlit reviewer UI
        ↓
Vertex AI / Gemini advisory assessment
        ↓
Strict parser + citation grounding
        ↓
Human reviewer decision
        ↓
Firestore decision record

Runtime: Cloud Run
Identity: dedicated user-managed service account
```

## Reused ideas from ControlSift

ProofStack reuses general design patterns from John's earlier MIT-licensed ControlSift research project:
- fail-closed output parsing
- clear separation of model input from analytical metadata
- machine-verifiable result integrity
- model output treated as evidence for evaluation, not authority
- synthetic-only public data boundary

ProofStack does not import the ControlSift dataset, experiment history, result scores or Git history.
