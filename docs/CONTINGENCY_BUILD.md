# Contingency MVP branch

Branch: `contingency/john-complete-mvp`

Purpose: maintain a complete, submission-safe ProofStack implementation that does not depend on unfinished teammate branches.

## Rules

1. This branch is explicitly John-owned contingency work.
2. Do not rewrite Git history to make contingency work appear to be another teammate's contribution.
3. If a teammate later delivers a stronger implementation, review and merge/cherry-pick that contribution normally.
4. Manual gold labels remain a human team task and are not generated by this branch.
5. Final metrics are not run until the manual gold set is complete and frozen.
6. Live NVIDIA, Vertex, Cloud Run and Firestore status must be reported exactly as verified.
7. The contingency branch may become the submission base if required, but only after contribution history and final facts are reconciled.

## Reused ideas from ControlSift

ProofStack reuses general design patterns from John's earlier MIT-licensed ControlSift research project:
- fail-closed output parsing
- clear separation of model input from analytical metadata
- machine-verifiable result integrity
- model output treated as evidence for evaluation, not authority
- synthetic-only public data boundary

ProofStack does not import the ControlSift dataset, experiment history, result scores or Git history.
